# proto/ — P0 空間モデル試作

計画書 §7 / 実装書 §19 の P0。**捨てる前提の試作**であり、品質基準・本番ビルドの対象外。
目的は「どの空間モデルがスマホで一番気持ちよく道を引けるか」を Ryo が実機で判断すること（決定 D1）。

## 3方式

| ディレクトリ | 方式 | URL |
|---|---|---|
| `proto/grid/` | グリッド（本命） | `/proto/grid/` |
| `proto/spline/` | 自由曲線（アンカー + スプライン） | `/proto/spline/` |
| `proto/hex/` | ヘックス | `/proto/hex/` |

## 比較を成立させるための共通化

`proto/shared/` が**地形と交通ロジックを一手に持つ**。3方式は **ProtoNetwork の実装 + 描画 + 入力だけ**を書く。
これにより地形と車の挙動が3方式で同一になり、比較対象が操作感と見た目だけに絞られる。

- `shared/network.ts` — `ProtoNetwork` 契約と経路探索（BFS）
- `shared/dummyTraffic.ts` — 車50台の共通ダミー交通
- `shared/terrain.ts` — 共通の固定地形（同一シードなら3方式で完全に同じマップ）

**各方式が地形を独自生成してはいけない。** それをやると Ryo が比べているのは空間モデルではなく
「たまたま生成された地形」になり、D1 の判断が無意味になる。`shared/terrain.test.ts` がこの性質
（決定論・建設可能面積・川の連続性）を固定している。

カメラ・テーマ・FPS HUD は本番の `src/render/` を共有する（`camera.ts` / `theme.ts` / `debugHud.ts`）。

## 触り方

```bash
pnpm dev
```

その後スマホの実機ブラウザで `http://<dev-vmのIP>:5173/proto/grid/` などを開く。

## 評価の観点（D1の判断材料）

1. 道を引くのが気持ちよいか（意図した線が一発で引けるか）
2. 誤操作の起きにくさ（パンとの取り違え、行き過ぎ、引き直しの手間）
3. 見た目の good さ（MachiScape のミニマルな方向性に合うか）
4. スマホでの指の届きやすさ・視認性
