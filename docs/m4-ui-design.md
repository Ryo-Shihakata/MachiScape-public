# M4 UI・見た目・アニメーション設計

> **この文書は設計の指定であり、実装者が判断で変えてよい範囲を明示している。**
> 作成: 2026-07-31 / 設計: Opus（親セッション）/ 実装: subagent（codex・Sonnet）
>
> 前提となる sim 側の仕組みは実装済み。この文書は「それをプレイヤーにどう見せ、どう触らせるか」だけを決める。

---

## 0. 設計の前提（守るべき制約）

| 制約 | 内容 |
|---|---|
| スマホ優先 | 幅360pxでも破綻しないこと。**タップ領域は最低 44×44 CSS px** |
| 画面下の段数 | 既に4段（ヒント / オーバーレイ / 区画サブ選択 / ツールバー）。**段を増やさない** |
| 数値入力の禁止 | 信号周期・秒数・スライダーは作らない（設計レビューで不採用。狭い画面に合わない） |
| 既定で静か | 情報は「必要なときだけ」出す。常設の凡例を増やさない |
| 性能 | 車の描画は毎フレーム・最大1,500台。60fps を守る |
| 依存方向 | `ui → render → sim` |
| 色 | `src/render/theme.ts` のトークン経由。16進の直書き禁止 |

## 1. 優先道路（交通整理）のUI

### 1.1 なぜ新しいツールにするか

既存のインスペクタ（移動ツール中のタップ）に混ぜる案も検討したが、**却下**する。

- インスペクタは「読む」ための場所で、「操作する」場所ではない
- 移動ツール中のタップでしか開かないため、**初見のプレイヤーが交通整理の存在に気づけない**
- 交通整理はオーナーが「これが無いと面白くない」と言った**遊びの中心**なので、道路・区画と同格の位置に置くべき

**採用: ツールバーに5つ目のツール「交通」を足す。** 段は増えない（ツールバーは横スクロール可）。

### 1.2 操作（1タップで完結させる）

「交通」ツールを選ぶと:

1. **対象になる交差点がマップ上に光る**（後述のマーカー）。どこを触れるかが一目で分かる
2. **交差点をタップするたびに状態が巡回する**:

   ```
   指定なし → 横（東西）を優先 → 縦（南北）を優先 → 指定なし → …
   ```

3. **ダイアログもメニューも出さない。** タップ＝即反映。誤操作はもう一度タップすれば戻せる
4. 対象外の場所をタップしたら、**理由をトーストで出す**（例: 「交差点ではありません」）

**なぜ巡回にするか**: 選択肢が3つしかなく、どれも即座に取り消せる。メニューを開かせるのは操作を1つ増やすだけで、狭い画面では損。

### 1.3 マップ上の表示

**A. 「交通」ツール選択中**

- **対象の交差点すべて**に、細いリング（円の輪郭）を描く。色は `theme.preview`（青）、alpha 0.5 程度
- リングの直径は 0.8 タイル程度。道路（幅0.5）より少し大きく、囲んでいることが分かる大きさ

**B. 優先が設定されている交差点（ツールに関係なく常に表示）**

プレイヤーが自分で置いたものなので、**ツールを切り替えても見え続ける**こと。ただし主張は控えめに。

- **優先軸を示す帯**: 交差点タイルの中央に、優先軸に沿った細い帯（長さ0.9タイル・太さ0.14タイル・角丸）を描く。色は `theme.good`（緑）、alpha 0.7
  - 「この向きが流れる」ことを、矢印ではなく**帯の向き**で示す。矢印は双方向なので嘘になる
- **譲る側を示す印**: 優先軸と直交する2本の進入方向それぞれに、停止線を描く
  - 交差点タイル中心から 0.42 タイル離れた位置に、進入方向と直交する短い線（長さ0.34タイル・太さ0.08タイル）。色は `theme.warn`（琥珀）、alpha 0.8
  - これは実際の停止位置と一致させること（sim の停止位置がずれていると嘘になる）

**C. 描画順**

交差点マーカーは **`buildingLayer` と `overlayLayer` の間**に専用レイヤを置く。理由:
- 道路・建物より上でないと隠れる
- 情報オーバーレイ（渋滞ヒートマップ等）より下にしないと、オーバーレイが読めなくなる

**D. 更新頻度**

マーカーは**建設操作・優先設定の変更時だけ描き直す**（`markDirty` に乗せる）。毎フレーム描かない。

### 1.4 状態の見せ方（ツールバー側）

「交通」ツール選択中は、**区画ツールと同じ位置にサブ行を出す**（段は増えない。区画のサブ行と排他）。

- サブ行には**現在の街の交差点の要約**を1行で出す: 例「交差点 12 / 優先を設定 3」
- **ボタンは置かない**（操作はマップ上のタップで完結するため）

### 1.5 文言（`src/i18n/ja.ts` に追記）

| キー | 文言 |
|---|---|
| `tool.traffic` | 交通 |
| `traffic.hint` | 交差点をタップすると、優先する向きが切り替わります |
| `traffic.summary` | 交差点 {total} / 優先を設定 {controlled} |
| `traffic.axisHorizontal` | 東西を優先 |
| `traffic.axisVertical` | 南北を優先 |
| `traffic.axisNone` | 指定なし |
| `traffic.notIntersection` | ここは交差点ではありません |
| `traffic.toast` | {axis}にしました |

**「東西 / 南北」と書くこと。** 「横 / 縦」はマップを回転できない今は同義だが、方角の方が地図として自然に読める。

### 1.6 インスペクタとの関係

移動ツールで交差点をタップしたときは、**インスペクタに交差点の情報も出す**（読む側の一貫性のため）。

- 「交差点」「優先: 東西 / 南北 / 指定なし」を表示
- **インスペクタからは変更させない**（操作は「交通」ツールに一本化する。2か所から変えられると、どちらが正なのか分からなくなる）

## 2. 車の見た目（Mini Motorways 風）

### 2.1 現状と方針

現在は角丸カプセル（round cap のストローク）1本。**形が単純すぎて車に見えない**というのがオーナーの指摘。

**方針: 平たい単色図形の組み合わせで「車らしさ」を出す。写実にしない。** アセット画像は使わない（計画書 §6: 画像アセット原則ゼロ）。

### 2.2 形

**自家用車**（`kind === 'car'`）

- **車体**: 角丸長方形。長さ 0.30・幅 0.15・角丸 0.05 タイル
- **屋根（キャビン）**: 車体の中央やや後ろ寄りに、明るい色の角丸長方形。長さ 0.12・幅 0.10・角丸 0.03
  - 位置は車体中心から**進行方向の逆に 0.02** ずらす（前が長い＝ボンネットに見える）
  - 色は車体色を**白へ 35% 寄せた**もの。テーマのトークンから計算する（新トークンを足さない）

**トラック**（`kind === 'truck'`）

- **運転席**: 角丸長方形。長さ 0.14・幅 0.17・角丸 0.04。車体の前端に置く
- **荷台**: 角丸長方形。長さ 0.28・幅 0.19・角丸 0.03。運転席の後ろに **0.02 の隙間**を空けて置く
  - 隙間があることで「連結している」ことが読める。隙間を0にすると1本の棒に見える
- 荷台の色は運転席より**暗く**する（車体色を黒へ 15% 寄せる）

**共通**

- **サイズは常に一定**（走行中・出入り中を問わず）。これは既存の回帰テストで守られている。**崩さないこと**
- 影は現状どおり（車体と同形・わずかにずらす・ぼかし）

### 2.3 色

- 自家用車: `theme.vehicleCar` / トラック: `theme.vehicleTruck`（既存）
- **車ごとの色のばらつきは付けない。** Mini Motorways は色に意味（目的地）を持たせている。このゲームで色を意味なく散らすと、後で色に意味を持たせたくなったときに使えなくなる

## 3. 車のアニメーション

### 3.1 ブレーキランプ（最優先。これが一番効く）

**渋滞というこのゲームの核を、車1台の見た目で読めるようにする。**

- 車が**減速している / 停止している**とき、車体の**後端**に小さな赤い点を描く
  - 直径 0.05 タイル、色は `theme.bad`、alpha は減速の強さに比例（0.3〜1.0）
- 判定は**描画側で行う**: 前フレームの位置との距離が「その車の期待移動量」より小さければ減速中
  - sim に新しい状態を持たせない（セーブが増えない）
  - 期待移動量は `TRAFFIC.VMAX` と tick 時間から求まる
- **交差点で譲っている車はこれで自然に光る**。優先道路を置いた効果が画面で読める

### 3.2 発進・停止のなめらかさ

- 位置は既に tick 間補間が入っている。**追加の緩急は付けない**
  - 理由: sim が「その tick にどれだけ進むか」を決めており、描画側で緩急を足すと sim の速度と食い違う。渋滞の見え方が嘘になる

### 3.3 建物への出入り

現状の実装（脚の最初/最後の辺で建物と補間、不透明度でフェード）を維持する。ただし1点だけ調整:

- **不透明度のフェードは、位置の補間より速く終わらせる**（`t` の 0〜0.6 でフェード完了）
  - 現在は位置と不透明度が同じ `t` で動くため、建物の真上でようやく消える。**建物の縁で消える**方が「入った」ように見える

### 3.4 車線変更の見た目

車線オフセットは実装済み。**追加のアニメーションは付けない**（交差点で弱める処理が既にある）。

## 5. 親が先に用意する継ぎ目（担当A/Bが衝突しないため）

実装の発注前に、親（Opus）が `src/render/gameScene.ts` に次を追加する:

```ts
/** 交差点マーカー1件ぶん。UI は sim の状態からこれを作って渡すだけ */
export interface IntersectionMarker {
  pos: TilePos;
  /** 優先軸。null は「対象だが未設定」 */
  axis: IntersectionAxis | null;
  /** 「交通」ツール選択中か（対象を光らせるかどうか） */
  highlighted: boolean;
}

// GameScene に追加
setIntersectionMarkers(markers: readonly IntersectionMarker[]): void;
```

- 専用レイヤを `buildingLayer` と `overlayLayer` の間に置く
- `setIntersectionMarkers` は `dirty` を立てる（毎フレーム描かない）
- 描画の中身（リング・帯・停止線）は§1.3の指定どおり親が実装する

これにより担当Aは `gameScene.ts` を触らずに済み、担当Bと並列に進められる。

## 6. 受け入れ基準

### 交通整理のUI

1. 「交通」ツールを選ぶと対象の交差点が光り、**タップのたびに 指定なし→東西→南北→指定なし と巡回する**
2. 設定した優先は**ツールを切り替えても見え続ける**
3. 譲る側の停止線が、**sim が実際に停止させる位置と一致している**
4. 対象外をタップしたら理由がトーストで出る
5. **段が増えていない**（画面下は4段のまま）。タップ領域 44px 以上

### 車の見た目とアニメーション

1. 自家用車とトラックが**形で**見分けられる（色だけに頼らない）
2. **サイズは走行中・出入り中を問わず一定**（既存の回帰テストを壊さない）
3. **減速・停止している車のブレーキランプが光る**。交差点で譲っている車で確認できること
4. 性能: 1,500台で60fpsを維持。**毎フレームのオブジェクト生成を増やさない**

- `pnpm typecheck` / `lint` / `test` / `build` がすべて終了コード0
