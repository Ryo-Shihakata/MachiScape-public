# M6 計画: 街に目的と選択肢を持たせる

オーナー判定「人口2000まで増やしたが、面白みが正直少ない」への回答。

**この計画の要点は、足りないのはコンテンツではなく「道路網で解くべき問題」だという診断。**
仕様書に書いてある施設5種とマイルストーンをそのまま実装しても、目標のある単調なゲームに
なるだけで終わる可能性が高い。順序と中身を変える。

---

## 1. 診断

### 1-1. 実測した事実

| 事実 | 確認方法 |
|------|----------|
| 施設は完全に未実装（`placeFacility` は「未実装」を返すだけ） | `src/sim/world.ts` |
| マイルストーンも未実装（`achievedMilestones` は空配列のまま） | `src/sim/world.ts` |
| **エリア購入の UI が無い**。op と価格計算はあるが触れない | UI 全体を検索して不在を確認 |
| **お金が制約になっていない**: 日次税収 517 に対し維持費 8.8（収入の1.7%）。150日で残高71,203 | ヘッドレス実測 |
| 人口は同じ道路網で約1730で頭打ち | ヘッドレス実測 |

### 1-2. いちばん重い問題: 悪い道路網が「見えない形で」需要を消している

D7 で入れた「1棟が同時に出せる車は1台まで」は、車の暴走を止め成長の頭打ちを解いた
正しい変更だった。しかし**副作用がある**。

上限に達した住宅は、次の出発抽選そのものを行わない（`traffic/trips.ts`）。したがって:

```
渋滞する → 車の回転が落ちる → 新しい車が出ない → 負荷が自動で下がる
```

という自己安定化が起きる。**D7 に書いた「上限に達している間の需要は消えるのではなく待つ」は
厳密には誤り**で、待ち行列も未処理件数も存在せず、出発機会そのものが消えている。

その結果:

- 人口1730の頭打ちは「道路網の限界を突きつけられた」ではなく**「なぜか成長が止まった」**に見える
- 失敗率は**実際に生成されたトリップしか数えない**ので、出発できなかった需要を評価できない
- プレイヤーは「道路を直せば良くなる」という因果を体験できない

**ゲームオーバーも時間的プレッシャーも要らない。要るのは「時間の圧力」ではなく「状態の圧力」。**

> 人口Xを支えながら、必要な移動のY%以上を処理し、物流を維持する

これならポーズできて、失敗しても復旧でき、それでいて緊張感が成立する。

### 1-3. 仕様書の施設は、道路網の判断を変えない

仕様書（実装書 §10）の5種を読み直すと、**どれも新しい交通負荷を作らない**。

| 施設 | 効果 | 道路の判断を変えるか |
|------|------|---------------------|
| 公園 | 満足度の下限を上げる | 変えない（失敗の影響を緩和するだけ） |
| 学校 | 入居抽選の重み×1.2 | 変えない |
| 病院 | 退去を4日連続に延長 | 変えない |
| 市役所 | 税収×1.05 | 変えない（余っている金がさらに増える） |
| スタジアム | 誘引力20 | **既存トリップの行き先を振り替えるだけ** |

人の移動の総量は住宅ごとの固定出発確率で決まるので、誘引力は「どこへ行くか」の配分でしかない。
**スタジアムを置いても総需要は増えない。** 置く場所を考える楽しさは、
「そこに置くと交通がどう変わるか」から生まれる。今の仕様ではそれが生まれない。

### 1-4. 実装して分かったこと: 処理率は道路網の質を映さない（W2 の実測）

未処理需要を数えられるようにしてから測ったところ、**処理率は道路網の良し悪しをほとんど
映さなかった**。

| 道路網 | 100日の人口 | 処理率 |
|--------|------------|--------|
| 密（横4・縦5タイル間隔） | 1728 | 21% |
| スカスカ（横8・縦10タイル間隔） | 1096 | 23% |

出発頻度を下げて上限の飽和を解いても同じで（0.002 で 61% / 62%）、
**差が出るのは人口だけ**（3216 / 1720）だった。

理由: **街は「移動時間が同じくらいになるまで」成長して止まる**。需要は失敗率が上がると
下がるので、道路網が悪い街は小さいところで釣り合い、良い街は大きいところで釣り合う。
つまり**道路網の質は処理率ではなく街の大きさに現れる**。

**したがって W3 の「3日連続で処理率85%以上」という品質ゲートは成立しない。**
どんな道路網でもだいたい同じ値になるので、条件として意味を持たない。

使えるのは絶対値ではなく次の2つ:

- **変化の方向**（昨日より悪くなったか）。施設を置いた直後など、**急に負荷が増えた瞬間**は映る
- **建物ごとの内訳**（どの住宅が出られずにいるか）。地図上で「ここが詰まっている」を見せる

W3 のマイルストーンは**人口を主軸に戻す**。品質は合格条件ではなく、
「次の目標まであと何が足りないか」を説明する材料として使う。

## 2. やること（順序が重要）

**この順序自体が仮説検証になっている。** 上から順に、効果が確かめられる単位で入れる。

### W1. エリア購入 UI（面白さの追加ではなく、遊べなくなる不具合の修正）

`buyDistrict` op と `districtPrice` は実装済み。UI が無いだけ。

- 解放済みチャンクに隣接する未購入チャンクを、マップ上に「買える土地」として薄く見せる
- タップで価格を確認 → 購入。価格は `DISTRICT_BASE_PRICE × DISTRICT_PRICE_GROWTH^n`
- 購入と同時にチャンクを生成して `districts` へ追加（sim 側は実装済み）

**これが無い限り、街は32×32で必ず終わる。** 最優先。

### W2. 未処理需要の記録（緊張感を作る核心）

**1棟1台の上限は維持する**（外すと車が暴走して D7 の問題に戻る）。
代わりに「本来なら発生していた移動」を数える。

- 日次で3つを集計する: **発生すべき移動 / 完了 / 未処理**
  - 未処理 = 上限で出発できなかった + 経路が無い + タイムアウト
- 上限で出発できなかったぶんは、**車を増やさずに数える**（住宅ごとに「出したかった回数」を数えるだけ）
- `Progress` に持たせ、既存の `tripsLastDay` / `failedLastDay` と並べる
- **処理率（完了 ÷ 発生すべき移動）**を街の健全度の主指標にする
- 分析カテゴリーに「未処理需要」を足し、どの住宅が出られずにいるかを地図上で見せる

これが入ると、初めて「道路が足りていない」がプレイヤーに見える。

### W3. マイルストーンを「人口 ＋ サービス品質」にする

仕様書の人口だけのマイルストーンは弱い。人口は既に唯一の成長指標であり、
報奨金は資金余りを悪化させるだけになる。

| 解放 | 条件 |
|------|------|
| 学校 | 人口100 |
| エリア購入 | 人口300 |
| 幹線道路 | 人口500 |
| 公園 | 人口500 |
| 3x速度 | 人口1000 |

**当初は「3日連続で処理率85%以上」という品質ゲートを置く計画だったが、
§1-4 の実測により取り下げた。** 処理率はどんな道路網でもほぼ同じ値になるので
条件にならない。人口を主軸に戻し、処理率は「次の目標まであと何が足りないか」の
説明に使う。

- **未達でもゲームオーバーにはしない。** 次の解放が保留されるだけ（確定済みの設計決定を守る）
- 「あと何が足りないか」を必ず1行で見せる。数値だけ出して放置しない
- 達成時にバナー＋効果音＋報奨金

### W4. 施設は2種だけ先に出す（5種一括はやらない）

D5 で承認済みの「垂直スライスで判定してから残りを決める」に戻す。
`FacilityDef` はデータ駆動なので、系を作れば残り3種は後から足すだけになる。

| 施設 | 効果 | 狙い |
|------|------|------|
| **学校** | 半径8内の住宅の発展を促す **代わりに、その住宅から追加の通学需要が発生する** | **負荷を生む施設** |
| **公園** | 半径5内の満足度の下限を上げる。追加需要なし | **負荷を生まない施設** |

**この対比が本題。** 学校は中央に置けば広く効くが交通が集中し、
周辺に置けば負荷は軽いが恩恵が狭い。**置く場所が道路の判断を変える**。
公園と並べることで「負荷を引き受けてでも置くか」という選択になる。

仕様書 §10 の学校の定義（入居重み×1.2、追加需要なし）は**この計画で改訂する**。

### W5. 経済を「高性能な手段を選ばせる」形にする

維持費を一律に上げるのは悪手。「儲からないから道路を引けない」という窮屈なゲームになる。
しかも現状は赤字でも残高が0に丸められるだけで、未払いの影響が無い。

役割を分ける:

| 対象 | 方針 |
|------|------|
| 通常道路・区画 | 安いまま。**試行錯誤を邪魔しない** |
| 幹線道路・橋・施設・エリア | 高い。**互いに予算を奪い合う** |
| 通常道路の維持費 | 低いまま |
| 幹線・橋の維持費 | 明確に高くする（今は幹線も通常も同じ1タイル扱い） |
| 撤去・引き直し | 無料か非常に安く。**資金ゼロでも復旧できること** |
| 大きな資金 | 人口ではなく**品質マイルストーンの一時金**を中心にする |

**調整目標は「維持費を収入の何%にするか」ではない。**

> 人口500の時点で、学校・新エリア・幹線1本の**すべては買えず、どれか1〜2個を選ぶ**

という実際の意思決定で定義する。時間で無限に貯まる以上、建設費は最終的に待ち時間にしかならない
ので、日次黒字の蓄積にも上限を設けるか、一時金中心に寄せる。

## 3. ここで止めて判定を受ける

W1〜W5 が入った時点で **プレイテスト③（Ryo）**。判定の問い:

1. 施設を「どこに置くか」で悩んだか
2. 処理率が下がったとき、道路を直す動機になったか
3. 次のマイルストーンを目指したいと思ったか

**面白くならなかった場合、不足はコンテンツではなく「道路網によって解くべき空間的な問題」
そのものだと切り分けられる。** 残り3種の施設を足しても解決しない、という判断ができる。
この切り分けができることが、5種一括ではなく2種にする理由。

## 5. プリモーテム: この計画が失敗するとしたら

「M6 を全部入れたが、やはり面白くなかった」と仮定したときの死因。

### 死因1: 処理率が下がっても痛くないので、道路を直す動機にならない

- **早期警報**: W2 の実測で、処理率が60%まで落ちても人口と税収がほとんど変わらない
- **回避策**: 未処理需要を満足度に直結させる。未処理が続いた住宅は退去する。
  「直さないと街が縮む」を体感できる強さまで上げる（**ゲームオーバーにはしない**）

### 死因2: 学校の通学需要が、道路の判断を変えるほどの量にならない

- **早期警報**: 学校を置く前後で、周辺の道路の流量オーバーレイが目に見えて変わらない
- **回避策**: 通学需要は「住宅ごとの追加の出発確率」として実装し、**量を balance.ts で調整可能に**する。
  置いた瞬間に流量オーバーレイが変わるのが見えるところまで上げる

### 死因3: 経済を締めた結果、ただ待つだけのゲームになる

- **早期警報**: 「新エリアを買いたいが金が無い → 3倍速で放置」が最適行動になる
- **回避策**: 大きな資金は日次黒字の蓄積ではなく**品質マイルストーンの一時金**から出す。
  蓄積に上限を設け、「待てば必ず買える」を成立させない。
  撤去と引き直しは無料に近くして、**金が無くても手は動かせる**状態を保つ

## 6. この計画の最も弱いところ

**「未処理需要を見せれば道路を直したくなる」は仮説であって、実証されていない。**

処理率が下がったとき、プレイヤーが「道路を直そう」ではなく「まあいいか」と思う可能性はある。
その場合、必要なのは指標ではなく**未処理が実際に痛いこと**（税収が落ちる・住民が出ていく）になる。
W2 を入れた時点で、処理率と人口・税収の連動が体感できる強さかを実測して確かめること。

なお、この診断は別系統モデル（GPT-5.6, reasoning=high）の設計レビューを踏まえている。
私の当初案は「仕様書の5種＋マイルストーン＋経済をまとめて実装」で、
D5 で承認済みの垂直スライス方針を理由なく巻き戻していた。
