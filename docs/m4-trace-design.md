# M4 追加設計: トリップが見える選択 / 幹線道路の操作

対象は M4 の残り2件。UI・デザインの設計はこの文書が正で、実装はこれに従う。

- **T6: トリップが見える選択** — 「どこからどこへ向かっているか」が分かる
- **T7: 幹線道路の操作** — sim にある `upgradeRoad` / `downgradeRoad` を触れるようにする

---

## T6: トリップが見える選択

### 1. 新しいツールは作らない

交通整理（T4）で5つ目のツールを足したばかりで、6つ目を足すとツールバーが破綻する。
**「選ぶ」は既にある**（パンツールでタップ → インスペクタが対象を見る）。
そこに「車も選べる」「選ぶと経路が見える」を足すのが最小で、既存の操作を壊さない。

### 2. 何がタップで選ばれるか

パンツールでタップしたとき、次の順で判定する。

1. タップ点から `PICK.VEHICLE_RADIUS_TILES`（**0.6タイル**）以内に車がいれば、その車を選ぶ。
   複数いれば近い方、同距離なら id の小さい方（決定論）
2. いなければ、これまで通りタイルを選ぶ

**当たり判定は「描かれている位置」で行う。** 車は tick 間で補間されて動いているので、
sim の tick 位置で判定すると、見えている車と最大 0.3 タイルずれて「押したのに選べない」が起きる。
したがって拾う処理は `src/render/gameScene.ts` に置く（描画位置を知っている唯一の場所）。
**「どの建物からどの建物へ」というデータは sim が持つ**（`src/sim/traffic/trace.ts`）。
依存方向は `ui → render → sim` のまま。

0.6タイルは、スマホで指の腹が触れる範囲を車1台ぶんより少し広く取った値。
広げすぎると「道路をタップしたのに車が選ばれる」が増えるので、これ以上は広げない。

### 3. 車を選んだときに見えるもの

**経路の二色分け。これがこの機能の核心。**

| 部分 | 見え方 | 意味 |
|------|--------|------|
| 走ってきた道 | 細い・彩度を落とした線 | どこから来たか |
| これから走る道 | 太い・明るい線 | どこへ行くか |
| 出発した建物 | 輪郭だけのリング | 家 |
| 目的地の建物 | 塗りのリング＋ゆっくり脈打つ | 目的地 |

矢印は使わない。交通整理（T4）で「道路は双方向なので矢印は嘘になる」と決めた判断と揃える。
**進行方向は「明るい方へ進む」で伝わる**ので、記号を足す必要がない。

線は車のレイヤーより下・道路より上に描く。車が線に隠れてはいけない。

復路（`leg === 'return'`）のときは家と目的地の役割が入れ替わる。
リングの意味も入れ替え、インスペクタに「復路」と明記する。**リングだけ入れ替えて
文字が無いと、家に向かっている車を「家から出た車」と読み違える。**

### 4. 建物を選んだときに見えるもの

インスペクタの既存の内容はそのまま。加えて:

- その建物が**出発元または目的地**になっている車の経路を、同じ二色で細く描く
- 描くのは最大 `PICK.MAX_TRACES_PER_BUILDING`（**12本**）まで。
  人気の商業には多数の車が向かうので、全部描くと線の束になって何も読めない
- インスペクタに「出発中 N台 / 向かっている M台」

住宅は D7（1棟1台）により出発中が常に0か1台になるので、住宅で見えるのは
「うちの車が今どこにいるか」。商業・工業では「どこから客・荷が来ているか」が見える。
**この非対称は狙い通り**で、住宅＝個の追跡、商業＝集まり方の把握、と役割が分かれる。

### 5. 選択が消えるとき

- 車が目的地に着く / 道路が撤去されて車が消える → **次のフレームで選択を自動的に外す**。
  古い経路を出したままにしない
- 空きタイルをタップ、Esc、ツールの切り替え → 外す

### 6. 描き直しの頻度

経路の線は**選択が変わったときと、車が辺をまたいだときだけ**引き直す。
毎フレーム引き直すと、線の長い経路（30タイル超）で無駄が出る。
「走ってきた/これから」の境目は車の現在位置なので、そこだけ毎フレーム動かす。

### 7. sim 側の契約

`src/sim/traffic/trace.ts`（純関数・テスト可能）:

```ts
export interface TripTrace {
  vehicleId: number;
  kind: 'car' | 'truck';
  leg: 'outbound' | 'return';
  /** 出発元の建物（復路でも「家」を指す。UI が役割を入れ替えて表示する） */
  homeBuildingId: number;
  homePos: TilePos;
  destPos: TilePos;
  /** 道路タイル列。建物アクセスの座標は含まない */
  path: readonly TilePos[];
  edgeIndex: number;
  edgeProgress: number;
  elapsedTicks: number;
  /** 残りの道路タイル数 */
  remainingTiles: number;
  /** 表示用の状態。i18n のキーに1対1で対応させる */
  status: 'driving' | 'waiting' | 'access' | 'dwelling';
}

export function traceVehicle(state: GameState, vehicleId: number): TripTrace | null;
export function tracesForBuilding(state: GameState, buildingId: number, limit: number): TripTrace[];
```

`status` の判定は既存の `phase` / `intersectionWaitSinceTick` / `mergeWaitSinceTick` から導く。
**新しいフィールドを `Vehicle` に足さないこと。** 車は1,500台ぶんメモリに乗るうえ、
表示のためだけの状態を sim に持たせると、セーブ対象外の transient が増えて設計が濁る。

### 8. インスペクタの文面

```
🚗 走行中
住宅 (12, 7)  →  商業 (18, 3)
経過 34秒 / 残り 12タイル
```

座標を出すのは、建物に名前が無いから。名前を付けるのは v2（愛着の話になる）。

## T7: 幹線道路の操作

### 1. 区画ツールと同じ形にする

区画ツールは選択中に「住 / 商 / 工」の3つが出る。道路ツールも同じ位置に3つ出す:

| ボタン | 操作 | 費用 |
|--------|------|------|
| 通常 | 今まで通り道路を引く | `COST_ROAD` |
| 幹線 | 幹線道路を引く | 道路が無い所は `COST_ROAD + COST_UPGRADE_ROAD`、既存の道は `COST_UPGRADE_ROAD` |
| 縮小 | 幹線を通常へ戻す | `COST_DOWNGRADE_ROAD` |

**新しい形を発明しない。** 区画で学んだ「ツールを選ぶと、その下に種類が出る」がそのまま効く。
ドラッグは道路ツールなので直線スナップのまま（D2）。

### 2. 「幹線」は更地からも引ける

既存の道の上でしか使えない仕様にすると、「幹線を引きたい」と思ったプレイヤーが
必ず2回なぞることになる。**1回のドラッグで引けること**を優先する。

実装は `commitDrag` の中で、道路の無いタイルへ `buildRoad` → 線全体へ `upgradeRoad` の
2つの op を続けて出す。どちらも部分適用（払えるところまで）なので、
資金が途中で尽きても矛盾した状態にならない。

### 3. プレビューは実費を出す

道路のプレビューは既にタイル単位で「払えるか」を出している。
**幹線・縮小でも同じ精度で出すこと。** 通常道路の費用のまま表示すると、
指を離した瞬間に想定の3倍取られる。

### 4. 見た目

幹線道路は既に太く描かれている（T5）。ツールバー側で足す表示は無い。
縮小モードでドラッグ中は、対象になる幹線タイルだけをハイライトする
（通常道路の上をなぞっても何も起きないことが、離す前に分かる）。

### 5. ショートカット

`Digit2` は道路ツール。押すたびに 通常 → 幹線 → 縮小 と巡回させる
（区画の `Digit3/4/5` と違い、道路は3つに1キーを割り当てる。数字キーが尽きている）。
